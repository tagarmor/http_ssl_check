
# SSL / HTTPS Certificate Audit Tool

> Audit, inspect and report on the TLS/SSL posture of any list of web targets —
> from a single command-line script to a full interactive dashboard.

---

## Overview

This toolkit gives security and IT audit teams a lightweight, dependency-minimal
way to validate the HTTPS/SSL configuration of web targets at scale. It covers
three complementary usage modes so it fits into any workflow, from a quick
ad-hoc check on a Raspberry Pi to an in-browser live scan session with real-time
progress and compliance scoring.

The tool performs, per target:
  1. TCP connectivity check on the target port
  2. TLS handshake and full certificate inspection (issuer, CN, validity dates,
     key algorithm and size, cipher suite, protocol version)
  3. HTTPS GET request with HTTP status capture and error classification

All results are saved to a timestamped CSV file under ./reports/.

## Components

### 1. certs.py — Standalone Script

A self-contained Python script. No web server or browser required.

  - Run from any terminal: python certs.py
  - Prompts for the path to a .txt file containing the list of targets
  - Performs TCP → TLS → HTTPS checks sequentially for each target
  - Outputs a timestamped CSV to ./reports/
  - Color-coded terminal output (green check / red cross per step)
  - Dependency auto-detection with clear install instructions on failure

Dependencies:
  pip install requests cryptography urllib3

Supported platforms: Windows, Linux (Kali), Raspberry Pi OS, macOS
Python compatibility: 3.9 through 3.14


### 2. backend_v2.py — Flask Local API Server

A local REST API that exposes the scanning logic over HTTP, enabling the
dashboard to trigger and monitor scans in real time.

  - Auto-detects a free port from the candidate list: 5151, 5152, 5153,
    8181, 8282, 8383, 9191, 9292 (designed to avoid corporate firewall blocks)
  - Listens on 127.0.0.1 only (local machine, not exposed to the network)
  - Asynchronous scanning with Server-Sent Events (SSE) for live progress
  - Saves CSV reports to ./reports/ on completion

REST Endpoints:
  GET  /ping                 Health check — confirms backend is running
  POST /scan                 Start a new async scan; returns { scan_id, total }
  GET  /stream/<scan_id>     SSE stream: log lines, progress %, and done event
  GET  /reports              List all saved CSV reports
  GET  /reports/<filename>   Download a specific CSV report
  POST /run                  Legacy synchronous endpoint (backward compatibility)

Start command:
  python backend_v2.py

Dependencies:
  pip install flask flask-cors requests cryptography


### 3. dashboard_https_ssl_v5.html — Interactive Dashboard

A single self-contained HTML file. No installation, no build step.

Usage modes:
  a) Online mode: open the file in a browser while backend_v2.py is running.
     The dashboard connects to the backend, accepts a domain list, triggers
     the scan, and streams progress line by line via SSE.

  b) Offline / standalone mode: open the file directly in a browser and load
     a CSV report previously generated by certs.py or backend_v2.py.
     Full visualization with no backend required.

Features:
  - 9 KPI cards: OK/Fail domains, TLS status, expiry, key algorithms, protocols
  - Compliance scoring: configurable A–D grade based on adjustable weights
      * HTTPS active
      * TLS version (1.2 vs 1.3)
      * Certificate validity / days to expiry
      * Key algorithm strength
      * Key size (bits)
    Grade thresholds are also fully adjustable by the auditor.
  - Real-time scan log streamed via Server-Sent Events
  - Interactive charts (Chart.js 4.4): status distribution, error types,
    TLS versions, key algorithms, expiry timeline
  - Filterable and sortable domain table with per-row compliance badge
  - Bilingual interface: English / Spanish (toggle in the UI)
  - Backend API base URL configurable directly in the interface
  - Compatible with Chrome, Edge and Firefox

## Input File Format

One entry per line. Lines starting with # are treated as comments and ignored.
Blank lines are skipped.

Supported formats:
  domain.com
  192.168.1.1
  domain.com/path
  192.168.1.1/api/health
  domain.com:8443
  192.168.1.1:8443
  domain.com:8443/path
  192.168.1.1:8443/api/health
  https://domain.com
  https://domain.com:8443/path

Default port is 443 if not specified.

Example targets.txt:
  # Production endpoints
  www.example.com
  api.example.com:8443
  192.168.100.10/health
  # Legacy server
  legacy.internal.corp:4443

## CSV Report Structure

File naming convention: report_http_ssl_YYYYMMDDhhmmss.csv
Location: ./reports/ (created automatically if it does not exist)

Fields:
  hostname          Original entry from the input file
  https_active      TRUE if HTTPS responded successfully; FALSE otherwise
  error_type        Error label when https_active is FALSE:
                      DNS_ERROR | TIMEOUT | SSL_ERROR | CONNECTION_REFUSED
  https_status_code HTTP response code (200, 301, 403, 500, ...)
  https_status_text HTTP status text (OK, Moved Permanently, ...)
  ssl_issuer        Common Name of the certificate issuer (CA)
  ssl_common_name   Common Name of the certificate subject
  ssl_valid_from    Certificate not-before date (YYYY-MM-DD)
  ssl_valid_until   Certificate not-after / expiry date (YYYY-MM-DD)
  ssl_key_algorithm Public key algorithm: RSA | EC | DSA | Ed25519 | Ed448
  ssl_key_size_bits Public key size in bits (e.g. 256, 2048, 4096)
  ssl_cipher_suite  Negotiated TLS cipher suite
  tls_version       TLS protocol version: TLSv1.2 | TLSv1.3

Note: when https_active is FALSE, all SSL/certificate fields are left blank.
SSL fields are populated only when both the TLS handshake and HTTPS request
succeed. This is by design to keep the data unambiguous.

## Quick Start

### Mode A — Standalone (no browser needed)

  1. Install dependencies:
       pip install requests cryptography urllib3

  2. Create a targets.txt file with one domain or IP per line.

  3. Run the script:
       python certs.py

  4. Enter the path to targets.txt when prompted.

  5. Review the color-coded output in the terminal.

  6. Find the report at:
       ./reports/report_http_ssl_<timestamp>.csv

  7. Optional: open dashboard_https_ssl_v5.html in a browser and load
     the generated CSV for visualization.


### Mode B — Backend + Dashboard (live scan with UI)

  1. Install dependencies:
       pip install flask flask-cors requests cryptography

  2. Start the backend:
       python backend_v2.py

     The terminal will show the port selected, e.g.:
       * Running on http://127.0.0.1:5151

  3. Open dashboard_https_ssl_v5.html in Chrome, Edge or Firefox.

  4. Set the backend URL in the dashboard settings if needed
     (default is http://localhost:5151).

  5. Paste your domain list into the text area and click "Start Scan".

  6. Watch real-time progress; the CSV report is saved automatically when
     the scan completes and can be downloaded from the dashboard.


### Mode C — Dashboard offline (load an existing report)

  1. Open dashboard_https_ssl_v5.html in a browser directly
     (no backend required).

  2. Click "Load CSV Report" and select a CSV file previously generated
     by certs.py or backend_v2.py.

  3. All KPIs, charts and the domain table populate immediately.

## SSL Verification Behavior

SSL certificate verification is intentionally disabled in both scripts.
This is a deliberate design decision:

  - The tool is an auditor, not a gatekeeper. Its purpose is to report on
    the actual state of certificates, including expired, self-signed, or
    misconfigured ones.
  - Enabling strict SSL verification would silently skip exactly the targets
    that need attention most.
  - urllib3 InsecureRequestWarning is suppressed at runtime for clean output.

The dashboard compliance scoring penalizes invalid or expiring certificates
independently of whether the HTTPS request succeeded.

## Compliance Scoring (Dashboard)

The dashboard calculates a weighted compliance score (0–100) per domain and
assigns a letter grade:

  Grade A — Excellent posture
  Grade B — Good posture
  Grade C — At risk
  Grade D — Critical posture

Default scoring weights (adjustable via sliders):
  HTTPS active        : required baseline
  TLS version         : TLSv1.3 preferred over TLSv1.2; older versions penalized
  Certificate validity: remaining days to expiry
  Key algorithm       : EC/Ed preferred; RSA accepted; DSA penalized
  Key size            : minimum thresholds per algorithm

All weights and grade thresholds are configurable per-session directly in
the dashboard interface.

## Platform and Environment Notes

  - Scripts are tested on Windows 10/11, Kali Linux, Raspberry Pi OS (Bookworm),
    Ubuntu 22.04/24.04 and macOS Sonoma.
  - On externally-managed Python environments (Kali, Raspberry Pi OS, Debian 12+):
      pip install <packages> --break-system-packages
    or use a virtual environment:
      python3 -m venv .venv && source .venv/bin/activate && pip install <packages>
  - The cryptography library API changed in version 42 (UTC-aware datetime fields).
    Both APIs are detected and handled automatically at import time.
  - Python 3.14 requires explicit import of importlib.util; handled in backend_v2.py.
